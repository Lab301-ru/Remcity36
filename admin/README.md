# Админка новостей · Ремсити36

Браузерная панель для ведения раздела **Новости** (`/news`).
Каждая новость автоматически становится **отдельной SEO-страницей** `/news/<slug>`,
которую индексирует Яндекс.

Архитектура построена по образцу рабочей админки lab301: вход по GitHub-токену,
визуальный редактор текста (Trix), загрузка картинок прямо в браузере со сжатием в WebP.

## Как открыть

**https://remcity36.ru/admin/** — пароля нет. При первом входе вставьте GitHub-токен
(сохраняется только в этом браузере, потом вход автоматический).

## Токен (один раз)

Подходит **любой** тип токена:

**Classic-токен** (надёжнее для репозитория организации):
- GitHub → Settings → Developer settings → Personal access tokens → **Tokens (classic)** → Generate new token
- scope **`repo`** (целиком)
- если включён SSO организации — на странице токена **Configure SSO → Authorize**

**Fine-grained токен:**
- Resource owner: **Lab301-ru** → репозиторий `remcity36`
- Repository permissions → **Contents: Read and write**
- токен должен быть **одобрен администратором** организации (иначе 403)

## Как добавить новость

1. **«+ Новая новость»**.
2. Заголовок (slug подставится сам), дата, короткое описание (для поиска), категория/тег.
3. **Обложка** — выберите фото, оно само сожмётся в WebP. Можно не добавлять.
4. **Текст** — визуальный редактор: жирный, списки, заголовки, ссылки. Картинки можно
   перетаскивать прямо в текст — они загрузятся и сожмутся автоматически.
5. **«Опубликовать»** — страница появится на сайте за ~1 минуту.

Публикация пишет напрямую в репозиторий через GitHub API (Contents): генерирует
страницу статьи `/news/<slug>/index.html`, обновляет список `/news`, `sitemap.xml`
и версию кэша `sw.js`.

## Пересборка из командной строки (для разработчика)

```bash
node admin/build.js
```

Перегенерирует все страницы из `news/posts.json`. Логика шаблонов — в `admin/generator.js`
(общая для браузерной админки и скрипта сборки). Поддерживаются и новости с готовым
HTML-телом (`bodyHtml`, из редактора), и старые структурированные (`blocks`).

## SEO-панель

В редакторе новости под текстом находится **центр управления SEO** — 21 вкладка
с автосохранением, live-превью и валидацией в реальном времени.

### Как устроено

Каждая настройка страницы **переопределяет** глобальную. Если поле пустое —
берётся значение из «⚙ SEO сайта» (кнопка рядом со списком новостей).

```
admin/seo/
  domain.js       типы, enum-константы, реестры (Schema.org, каналы превью, AI-краулеры)
  application.js  генерация meta/JSON-LD/sitemap/robots, валидация, анализ, оценка, автоматизация
  fields.js       декларативное описание всех 21 вкладки
  ui.js           каркас панели, стор, автосохранение, рендерер полей
  widgets.js      15 кастомных виджетов (превью, анализ, оценка, история…)
  seo.css         стили панели
```

Слои разделены: генерация тегов живёт только в `application.js`, компоненты
её вызывают и рендерят результат.

### Вкладки

| Группа | Вкладки |
|---|---|
| Контент | Основное · Превью в поиске · Изображения |
| Соцсети | Open Graph · Twitter Card |
| Разметка | Микроразметка · Sitemap · Хлебные крошки |
| Организация | Авторство · Локальное SEO · Соцсети |
| Технические | Редиректы · Свой Head · Индексация · AI и нейросети |
| Аналитика | SEO-анализ · SEO-оценка · Core Web Vitals · Предпросмотр · История · Автоматизация |

### Расширяемость

Новое поле, тип разметки или канал превью добавляется **одной записью в реестр** —
существующие компоненты не меняются:

- новое поле → запись в `fields.js`
- новый тип Schema.org → запись в `schemaRegistry` (`domain.js`)
- новый канал превью → запись в `previewChannels`
- новый AI-краулер → запись в `aiDirectivesRegistry`

### Где хранятся данные

| Что | Где |
|---|---|
| SEO страницы | `news/posts.json` → `posts[i].seo` |
| Глобальные значения | `news/posts.json` → `site.seoDefaults` |
| Редиректы | `seo/redirects.json` + страницы переадресации |
| История изменений | `seo/changelog.json` |
| robots.txt | генерируется из AI-директив |

### Ограничения статического хостинга

- **Редиректы.** GitHub Pages не отдаёт настоящий 301, поэтому создаётся страница
  с мгновенным `meta refresh` + `canonical` — поисковики трактуют её как постоянный
  редирект и переносят вес на новый адрес.
- **Core Web Vitals.** Измеряются через публичный API Google PageSpeed Insights по
  опубликованному адресу. Без API-ключа Google ограничивает частоту запросов —
  ключ можно вписать во вкладке, он хранится только в браузере.
- **Генерация описаний ИИ.** Не подключена: серверной части нет, а обращаться к API
  нейросети из браузера нельзя — ключ попал бы в открытый код сайта. Кнопка
  «Описание из текста» решает ту же задачу локально, без ключей.
